# 文章图片备份工具

把文章里引用的网络图片**下载到文章自己的文件夹**，并把链接改成本地相对引用。

改完之后，图片和文章在一起，图床跑路、CDN 防盗链、图片被删，都不影响你的站点。

```
改之前：![image.png](https://q8.itc.cn/images01/xxx.png?x-oss-process=image/resize,w_1000)
改之后：![image.png](1681e27ae93c4f028728dda973729efa.png)
```

工具支持两种用法：

| 模式 | 源文件夹 | 适合什么时候 |
| --- | --- | --- |
| **导出备份** | **完全不动** | 想留一份干净备份，不想碰原稿 ← 推荐 |
| 原地备份 | 会被改写 | 想直接把站点改成图片本地化 |

---

## 一、怎么用

> **先说运行环境**：这个工具是用 Python 写的。双击 `.bat` 时，它会自己按顺序找：
> 系统 PATH 里的 python → WorkBuddy 自带的 Python → 常见安装目录。
> 找到了就直接用，不用你操心。
>
> 你这台电脑的 `PATH` 里只有一个 **0 字节的微软商店占位符**（名字叫 python，实际一运行就退出），
> 真正能用的是 WorkBuddy 自带的那个。启动器已经会自动跳过假货、找到它。
>
> 如果哪天 WorkBuddy 卸载了、或文件被清理，双击会弹出提示告诉你怎么办（装一个 Python 就行，
> 或者设一个 `PYTHON_EXE` 环境变量指向任意 `python.exe`）。

**双击 `图片备份工具.bat`**，会出现菜单：

```
==================================================================
  文章图片备份工具
==================================================================

  源目录：C:\Users\13202\Desktop\posts
  备份到：（未设置）

  [1] 预览        —— 只看会做什么，不写任何文件
  [2] 导出备份    —— 复制到上面的备份文件夹，源目录完全不动
  [3] 原地备份    —— 图片直接存回文章目录（会改原文件）
  [4] 设置源目录  —— 要备份哪个文件夹
  [5] 设置备份目录
  [6] 打开报告文件夹
  [0] 退出
```

### 只想备份、不动原文件夹（你要的这种）

1. 按 `4`，把**要备份的文件夹**粘贴进去（可以直接把文件夹从资源管理器拖进黑窗口）
2. 按 `5`，把**备份到哪个文件夹**粘贴进去。这个文件夹不存在会自动创建
3. 按 `2`，开始导出

跑完之后，原文件夹一个字节都不会变，备份文件夹里是「文章 + 本地化图片」的完整副本。

### 想把站点本身改成图片本地化

按 `3`。图片会存回文章目录，链接就地改写。

> 提示：也可以把任意文件夹**直接拖到 `图片备份工具.bat` 上**，它会作为源目录打开菜单。

### 会自动处理哪些写法

| 情况 | 是否处理 |
| --- | --- |
| `![说明](https://.../a.png)` | ✅ 下载并改写 |
| `![说明](//q1.itc.cn/a.jpg)` 协议相对地址 | ✅ 补成 https 后下载 |
| `![说明](https://.../a.jpg?x-oss-process=image/resize,w_1000/format,webp)` | ✅ 自动去掉压缩参数，取**原图** |
| `<img src="https://...">` HTML 标签 | ✅ 只替换 src，其他属性不动 |
| front matter 里的 `featured_image_preview` / `images` | ✅ 会下载，但**默认不改链接**（见第六节） |
| 已经是本地相对路径 `![](a.png)` | 跳过；文件丢了会在报告里提示 |
| ` ``` ` 代码块里的示例文字 | 跳过，绝不乱改 |
| 站内绝对路径 `/images/a.png` | 跳过，交给 Hugo 管 |

> 关于「取原图」：很多图床的 URL 尾巴上带 `?x-oss-process=image/resize,w_1000/format,webp`，
> 那是个**在线压缩**参数，实测一张 95KB 的 PNG 会被压成 26KB 的 webp。工具默认把这层参数剥掉，
> 拿真正的原图；只有剥掉后服务器报 403/404 时，才退回用带参数的地址。

## 二、导出模式会生成什么

假设源目录是这样（还没本地化）：

```
我的文章/
└── post-002/
    └── index.md          ← 里面是 https 图片链接
```

`[2] 导出备份` 到 `C:\博客备份` 之后：

```
C:\博客备份\                          ← 源目录完全没动
├── .image-backup-manifest.json       ← 记录「哪个网址存成了哪个文件」
└── post-002\
    ├── index.md                      ← 链接已改成本地文件名
    ├── .index.md.bak                 ← 导出前的原件（多一层保险）
    ├── 6b6ba06f...951.jpg
    ├── 18620509...2a3.jpg
    └── ...（其余图片）
```

目录层级和源文件夹保持一致，可以直接整个丢进 Hugo 的 `content/posts` 里用。

**每篇都会多一份 `.index.md.bak`**，内容是导出前 `index.md` 的逐字节副本。它的用处是：备份文件夹自成一套——万一以后原目录被误删、或者被别的工具改乱，备份里还留着「改写之前长什么样」，可以随时对比、随时还原。源文章内容变了，下次导出会同步刷新这份 `.bak`；没变就不动。

以点开头，Hugo 不会理它，也不影响你直接把备份目录当站点用。不想要这个 `--no-backup` 关掉即可。

## 三、原地备份会生成什么

```
post-001/
├── index.md              ← 图片链接已改成本地
├── .index.md.bak         ← 改动前的原件（只在第一次运行生成，不会被覆盖）
├── 1681e27a...efa.png
└── ...
```

`.index.md.bak` 以点开头，Hugo 不会理它。确认改得没问题后可以删掉。

两种模式共用的东西：

- **`_tools/image-backup/_manifest.json`**（导出模式下是备份目录里的 `.image-backup-manifest.json`）
  记录「哪个网址存成了哪个文件」，重复运行靠它保持文件名稳定，别删。
- **`_reports/backup-时间.txt`** 每次运行一份报告，失败清单也写在里面。

### 重复运行安全吗？

安全。

- 已经本地化过的文章会被识别为「没有网络图片」，直接跳过
- 上次下载失败的图，下次自动重试
- 导出到同一个文件夹时，内容没变的文件会被跳过，不会重复下载
- 目标文件夹里**已有的其它文件不会被删除**，只覆盖同名文件

所以「定期备份」就是反复按 `2`，没有副作用。

## 四、图片没下载成功怎么办

报告里会列出失败清单，**链接会保持原样**（不会变成坏链接），原文章依然能用。常见原因：

| 报错 | 原因 | 办法 |
| --- | --- | --- |
| `403 Forbidden` | 图床防盗链 | 换成浏览器里能打开的地址，或手动下载后改名放进目录 |
| `404` | 原图已被删除 | 只能找备份（网页快照 / 图床后台） |
| `timed out` | 网络抖动 | 直接再运行一次 |
| `返回的不是图片` | 链接指向的是网页而不是图片 | 手动确认链接 |

## 五、图片放进来了，但网页上不显示

工具只负责文件和 Markdown，图片能不能显示取决于 Hugo 怎么发布 page bundle（文章文件夹）里的资源。

先确认：`hugo server` 打开那篇文章，按 F12 看图片是不是 404。

如果是 404，说明资源没被发布，在 `hugo.toml`（或 `config.toml`）里加：

```toml
[build]
  publishResources = true
```

Hugo 0.123 以后的版本默认就是 `true`，老版本要手动加。加完重启 `hugo server`。

> 你用的是 Chirpy 主题，它自带图片渲染钩子（render hook），正常情况下相对路径的图片会被
> 自动识别为 page resource 并发布，多数人不需要改配置。

## 六、怎么定期备份

### 最简单的：定期按一次 `[2]`

导出到网盘同步目录（比如 `C:\Users\你的用户名\OneDrive\博客备份`），Windows 自己会往云端同步。

### 或者完全自动：Windows 任务计划程序

1. 按 `Win + R`，输入 `taskschd.msc`，回车
2. 右侧点「创建基本任务」，名字随意，比如「博客图片备份」
3. 触发器选「每天」，时间随便定个你不用电脑的点
4. 操作选「启动程序」，三个框分别填（**三个都要填，缺一个就跑不起来**）：

   **程序**（用哪个引擎跑）——要填 Python 的**完整路径**，不能只写 `python`：

   ```
   C:\Program Files\WorkBuddy\resources\vendor\python\python.exe
   ```
   或者
   C:\Users\13202\AppData\Local\Programs\Python\Python315\python.exe

   > 为什么不能写 `python`：很多电脑（包括这台）PATH 里的 `python` 是微软商店的假占位符，
   > 0 字节，一执行就退出且不报错，任务计划里只会显示一个看不懂的失败码。
   > 如果你自己装过 Python，换成自己的路径，比如 `C:\Python312\python.exe`。

   **参数**（让它做什么）——三段，引号照抄：

   ```
   "C:\Users\13202\Documents\2019527xyz网站备份\_tools\image-backup\backup_images.py" "C:\Users\13202\Documents\GitHub\blog\content\posts" --dest "C:\Users\13202\Documents\2019527xyz网站备份\备份"
   ```

   > `--dest` 后面换成**真实存在的硬盘目录**。别填光驱盘符（`设备未就绪`）、
   > 也别填不存在的盘。可以先在资源管理器里建好文件夹，再复制它的路径。

   **起始于**（在哪个目录干活）：

   ```
   C:\Users\13202\Documents\2019527xyz网站备份\_tools\image-backup
   ```

5. 保存后右键任务 →「运行」，等几秒看 `_tools/image-backup/_reports` 里有没有新报告。
   **有报告 = 成功**；没报告就去「上次运行结果」看错误码。

> 想先确认参数对不对，可以把「参数」那行原样粘到命令行里跑一次（前面加上 Python 完整路径）。
> 能跑通再放进任务计划，免得每天默默失败。

## 七、关于 front matter 里的封面图

有些文章的头部有这样的字段：

```yaml
featured_image_preview: https://q6.itc.cn/xxx.jpeg?x-oss-process=image/resize,w_1000
images:
- https://q6.itc.cn/xxx.jpeg?x-oss-process=image/resize,w_1000
```

`images` 是给搜索引擎和社交平台分享卡片用的（og:image），必须是**完整的绝对网址**，
改成文件名反而会让分享卡片失效。所以默认策略是：**图片照常下载备份，字段里的网址不动**。

如果你明确知道自己的主题支持页面资源写法，想一并改掉，加 `--rewrite-front-matter`。

## 八、命令行参数

```bash
# 导出备份（源目录只读）
python backup_images.py "C:\Users\13202\Desktop\posts" --dest "C:\博客备份"

# 原地备份
python backup_images.py

# 预览，不改任何文件
python backup_images.py --dest "C:\博客备份" --dry-run

# 其它
python backup_images.py --workers 10            # 并发数，网络好可以调高
python backup_images.py --keep-query            # 保留压缩参数（不推荐，会存成缩略图）
python backup_images.py --no-backup             # 不留 .index.md.bak（原地/导出模式都生效）
python backup_images.py --rewrite-front-matter  # 连 front matter 的图片地址一起改
python backup_images.py --limit 3               # 只处理前 3 篇，用来试水
python backup_images.py --menu                  # 打开菜单
```

返回码：`0` 全部成功，`3` 有图片没下载成功，`2` 参数或目录有问题，`1` 没找到文章。

**安全限制**：备份目录不能等于源目录，也不能放在源目录里面（否则会把自己备份进去），
工具会直接拒绝并提示。

## 九、放在这里会不会被 Hugo 当成文章

不会。`_tools` 以 `_` 开头，Hugo 会忽略这类目录。`.image-backup-manifest.json`、`.index.md.bak` 同理。

如果你不放心，把整个 `image-backup` 文件夹移到 `posts` 外面也照样能用——
工具会自动往上找含 `index.md` 的目录作为默认源目录，或者用 `[4]` 手动指定。
