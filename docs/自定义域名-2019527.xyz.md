# 站点域名：2019527.xyz

> 站点现在的正式地址是 **https://www.2019527.xyz**（裸域 `2019527.xyz` 与 `www` 都能打开，
> `www` 会 301 到裸域）。以下三处必须保持一致，否则会出现"样式全丢"或"Site not found"。

| 位置 | 现在填的值 |
| :--- | :--- |
| `config/production/hugo.toml` → `baseURL` | `https://2019527.xyz/`（**结尾必须有斜杠**） |
| `static/CNAME` | `2019527.xyz` |
| GitHub 仓库 Settings → Pages → Custom domain | `2019527.xyz` |

---

## 一、一条硬规则：一个仓库只能绑一个域名

GitHub Pages 对每个仓库只认**一个**自定义域名。如果两个域名的 DNS 都指向 GitHub 的 IP，
只有设置里填的那一个能打开，另一个会返回：

```
Site not found · GitHub Pages
```

这就是 `444527.xyz` 后来打不开的原因——不是 DNS 坏了，也不是证书过期，而是仓库的
Custom domain 已经改成了 `2019527.xyz`，`444527.xyz` 不在名单里，被 GitHub 直接拒绝。

**想让两个域名都能用**，只有两个办法：

1. 在域名商那边给 `444527.xyz` 设一条 **URL 转发 / 301 跳转**到 `https://2019527.xyz`
   （阿里云：域名列表 → 解析 → 域名转发；Cloudflare：Rules → Redirect Rules）。
   读者输入旧地址会自动跳到新站，页面内容不变；
2. 再开一个仓库做镜像部署，各自绑一个域名（两套 Actions，维护成本翻倍，不太建议）。

---

## 二、以后换域名，要改的位置

按顺序改，漏一处就会出现半新半旧的状态：

1. `config/production/hugo.toml` 的 `baseURL`（决定 og:image、RSS、搜索索引的绝对地址）；
2. `static/CNAME` 改成新域名（**不要带 `https://`、不要带斜杠**）；
3. GitHub 仓库 Settings → Pages → Custom domain 填同一个域名，保存；
4. 三篇法务页正文里提到的域名：`content/about|privacy|disclaimer/index.md`；
5. 站内工具页 `static/tools/xiezuo.html` 里的 `var SITE = "https://..."`；
6. `docs/` 下的文档（教程里到处都是示例链接）。

改完推送，等 Actions 跑完；如果 HTTPS 一时打不开，先把 Pages 里的
**Enforce HTTPS** 关掉，等证书签发（一般几分钟到几小时）再打开。

---

## 三、DNS 怎么填（阿里云为例）

在域名解析里保留这两组记录，别的不影响：

| 记录类型 | 主机记录 | 记录值 |
| :--- | :--- | :--- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `wangzhiman123.github.io` |

四个 IP 是 GitHub Pages 的固定地址，缺一个也能用，但建议照抄四个（官方要求全部配齐）。
解析生效一般 10 分钟内，`nslookup 2019527.xyz` 能返回上面任意一个 IP 就算生效。

> 域名必须完成**实名认证**，否则阿里云会把解析接管到 `overdue.aliyun.com`，表现为
> 502 或打不开。这个坑踩过一次，域名列表里看到红色"实名认证"提示就先提交审核。

---

## 四、出现 "Site not found" 时的排查顺序

按这个顺序查，基本三步内能定位：

1. **Custom domain 填的对不对**：仓库 Settings → Pages，看里面的域名与 `static/CNAME`
   是否一致。不一致就以 CNAME 为准，重新填一遍并保存。
2. **DNS 是否指向 GitHub**：`nslookup 你的域名`，结果不是 `185.199.x.153` 就是 DNS 问题，
   与 GitHub 无关。
3. **证书是否卡住**：Pages 里如果显示 "Certificate is being provisioned"，等；
   如果一直失败，把 Custom domain 删掉重新添加一次，会重新触发签发。

另外：`.xyz` 域名在国内部分网络环境下解析偶尔抖动，遇到"只有某个网络打不开"，
先换网络或换 DNS（223.5.5.5 / 1.1.1.1）复测，再判断是不是站点问题。
