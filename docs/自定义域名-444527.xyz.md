# 把 444527.xyz 接到 GitHub Pages 上

> 站点代码这边已经改完了（`baseURL` 已改成 `https://444527.xyz/`，`static/CNAME` 已添加并推送）。
> 现在只剩阿里云的 DNS 设置。**在 DNS 配好之前，网站会一直是打不开的状态**，这是正常的。

---

## 诊断结论：一个能通的域名，一个不能通

同一个阿里云账号下，你的 `2019527.xyz`（原来的 Chirpy 博客）**是完全正常的**：

| 域名 | 解析结果 | 打开结果 |
| :--- | :--- | :--- |
| `2019527.xyz` | 185.199.108/109/110/111.153 | **200 OK**，正常显示 |
| `www.2019527.xyz` | 同样四个 IP | 正常 |
| `444527.xyz` | **CNAME → `overdue.aliyun.com`** | **502**，打不开 |

`overdue.aliyun.com` 是阿里云的域名问题提示页。既然同账号的 `2019527.xyz` 一切正常，
说明**问题只出在 444527.xyz 这个域名本身，不是账号、不是 GitHub、也不是网络**。

`444527.xyz` 是 10 月 21 日注册的，到今天是第 8 天。最可能的原因是：
**域名注册后逾期未完成实名认证**，阿里云就把解析接管到了这个提示页。

---

## 一、先确认并解决域名状态（必须先做这一步）

浏览器打开：<https://dc.console.aliyun.com/next/index#/domain/list/all-domain>

跟旁边的 2019527.xyz 对比着看，找到 **444527.xyz**：

| 看到什么 | 说明 | 怎么办 |
| :--- | :--- | :--- |
| 状态列有 **「实名认证」红色提示 / 未实名 / 认证逾期** | 逾期未实名，解析被接管 | 点「实名认证」，上传身份证人像面 + 国徽面，提交 |
| 有 **未支付订单 / 待续费** | 欠费也会被接管 | 点「费用」把订单付掉 |
| 和 2019527.xyz 一样显示 **已实名** | 那就只是解析记录填错了 | 直接做第二步 |

> 实名审核一般几小时到 1 个工作日。审核通过后，阿里云会自动解除接管，
> 那时 `nslookup 444527.xyz` 就不再返回 `overdue.aliyun.com`。
> **实名没通过之前，下面第二步填什么都没用。**

---

## 二、删掉错误的那条解析

还是 444527.xyz 那一行，点右边的 **「解析设置」**（或「云解析 DNS」）。

在记录列表里找到这样一条：

```
记录类型：CNAME
主机记录：@
记录值：  overdue.aliyun.com     ← 就是它，删掉
```

点它右边的 **「删除」**。

> 如果你的列表里根本没有这条，跳过本步，直接做第三步。
> 注意：`@` 代表 `444527.xyz` 本身，`www` 代表 `www.444527.xyz`。

---

## 三、添加 5 条新记录

点 **「添加记录」**，按下表填，一共 5 条。

**这 5 条其实就是照抄 `2019527.xyz` 的设置**——它的解析已经验证过是通的，
所以你也可以先打开 2019527.xyz 的「解析设置」看一眼，照着搬过来，不会错。

| 记录类型 | 主机记录 | 记录值 | TTL |
| :--- | :--- | :--- | :--- |
| A | `@` | `185.199.108.153` | 10 分钟 |
| A | `@` | `185.199.109.153` | 10 分钟 |
| A | `@` | `185.199.110.153` | 10 分钟 |
| A | `@` | `185.199.111.153` | 10 分钟 |
| CNAME | `www` | `wangzhiman123.github.io` | 10 分钟 |

几个注意事项：

- **记录值末尾不要加点**，不要写成 `wangzhiman123.github.io.`
- 前 4 条是 GitHub Pages 的固定 IP，四条必须都加，少一条可能间歇性打不开
- 主机记录只填 `@` 或 `www`，**不要填完整域名** `444527.xyz`
- 如果弹出「是否保留原有记录」，选保留，别的手不要动
- 注意 `www` 那条指向的是 **`wangzhiman123.github.io`**（没有 `/blog`），别写成 2019527 那个

---

## 四、等生效，然后回 GitHub 点两下

DNS 生效一般 **5～10 分钟**，最长 24 小时（改记录比新增记录快）。

想自己确认：按 `Win + R`，输入 `cmd`，回车，粘贴这条再回车：

```
nslookup 444527.xyz
```

看到 `185.199.108.153` 这类地址就说明生效了；还看到 `overdue.aliyun.com` 就再等等。

生效后回到这个页面：<https://github.com/wangzhiman123/blog/settings/pages>

1. 点自定义域名输入框下面的 **「Check again」**
2. 等它变成绿色的 `DNS check successful`
3. 勾上 **「Enforce HTTPS」**（这一步可能要等十几分钟才可点，灰的就过会儿再来）

---

## 五、结果

配置完成后，两个地址都能用：

- `https://444527.xyz/` ← 主地址
- `https://www.444527.xyz/` ← 会自动跳到主地址

原来的 `https://wangzhiman123.github.io/blog/` 会自动跳转到 `https://444527.xyz/`，这是正常现象。

---

## 如果是域名本身有问题（未实名/欠费）

那 DNS 怎么填都不会生效，必须先解决域名状态。解决完再做第二步。

实在不想折腾域名，随时可以退回：在 Pages 页面点 **「Remove」** 删掉自定义域名，然后告诉我，我把 `baseURL` 改回 `https://wangzhiman123.github.io/blog/` 再推一次，网站立刻恢复。
